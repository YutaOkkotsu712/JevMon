# Security, instruction and coverage audit — 2026-09-23

Three questions: does running the bot on a server expose the Showdown password or the TypeSafe key;
do the instructions and payload say anything untrue; and which moves, abilities and items in the Gen 9
Random Battle pool are not modelled. Every fix was checked by running it, and the last section scores the
16 live battles against a fixed yardstick.

## Security

**No secret leaks.** The Showdown password goes only to a hardcoded
`https://play.pokemonshowdown.com/api/login` with redirects refused; the assertion goes back over `wss`,
which is enforced whenever credentials are set. The TypeSafe key goes only to a hardcoded HTTPS endpoint,
also with redirects refused. Errors are swallowed without their text. Neither value appears in any file
outside `.env` — logs, `dist/`, the image and its layer history were all searched for the actual values.
`.env` is excluded from the Docker build context and is sent to the server separately, owner-only.

**Opponent text never reaches the model.** A battle was fed a hostile username, nickname, chat line,
`-message` and `raw` line; none of them appear in the Jev payload. The live view escapes every string it
renders.

`npm audit`: 0 vulnerabilities in a two-package production tree.

Fixed:

| Finding | Fix |
|---|---|
| On Linux, the `./logs` bind mount is created root-owned and the uid-1000 container cannot write to it. The bot stays `Up` and records nothing. Docker Desktop on the Mac hides this. | The deploy script creates `logs` as uid 1000, mode 700, and proves the container can write to it. |
| The live view sent `Access-Control-Allow-Origin: *` and ignored the Host header, so any site open in the browser could read our team and choices while the SSH tunnel was up, directly or by DNS rebinding. | No CORS header; requests not addressed to a loopback name get 403. The extension still works through its host permission. |
| `MAX_BATTLES` lived in memory. A failed login or crash, restarted by Docker, handed the bot a fresh allowance of paid battles. | Counted in `logs/battles-played`, when a battle starts, across restarts; unreadable fails closed. |
| The container ran with a writable filesystem, full default capabilities and no limits. | Read-only root, all capabilities dropped, `no-new-privileges`, 512 MB memory and 128 process caps. Measured at 45 MB idle. |
| The deploy script would `rsync --delete` into any remote folder, including `.` or one holding other data, and asked for a password three times. | Plain folder names only; refuses a non-empty folder that is not an earlier deploy; one shared SSH connection, so one prompt. Warns if the server's Docker is older than 28. |
| `.env` on the Mac was world-readable (644). | Now 600. |

All of the deploy behaviour was rehearsed against a throwaway Linux server running real sshd and Docker:
one authentication per deploy, the refusals, the port refused on the server's own address, 403 for a
rebound name through a real tunnel, and a redeploy that removes stale files while keeping logs, the battle
count and `.env`.

Still yours to do on the server and accounts:

- The Showdown password is 5 characters. Use a long random one, on an account made for the bot.
- Log in with an SSH key and turn off password login; allow only SSH through the firewall.
- Keep Docker at 28 or later. Older versions let other machines on the same network reach ports published
  on 127.0.0.1.
- Anyone who can run `docker` on the server can read the environment with `docker inspect`, which is the
  same as root. Rotate the password and key if the server is ever compromised.
- `ACCEPT_CHALLENGES_FROM=*` lets strangers spend the 15-battle allowance. Name your own account to keep
  it for your games.

## Instructions and payload

Every field named in the instructions and glossary was checked against code, and against payloads rebuilt
from the 464 logged decisions with the current code.

Fixed:

- **`teamReserveUtility` was never sent.** The instructions told the model to read it, but `reserveUtility`
  was imported and never called. The rule is now stated directly and the dead function removed.
- **"Type immunity" was the default explanation for any zero.** Mirror Coat into Espeon was reported as
  `takesNothingFromIt: type immunity` beside a `conditionalDamage` block showing a 127–173% return, and so
  was Endeavor at equal HP. A type immunity is now claimed only when the type chart says so; moves that
  return damage taken are left to `conditionalDamage`; Endeavor gives its real reason.

Measured cost of these and the first coverage fixes: 2 of 464 decisions moved from the reduced to the
minimal tier, and the median payload grew by 8 bytes.

**Open question — the minimal tier.** 222 of 464 decisions (48%) are sent at minimal detail, which drops
`ifTheySwitch`, item triggers (Weakness Policy, Rocky Helmet), status and weather projections, residuals and
opposing PP. The instructions alone are about 10 KB of the 28 KB budget. The budget is a relevance choice,
not the model's limit (about 70 KB), so this is a trade-off to decide rather than a bug.

## Move, ability and item coverage

The pool: 509 species, 348 moves, 203 abilities, 59 items. Every damaging move was run through the damage
pipeline; none fails or silently returns zero. Endeavor, Super Fang, Ruination, Seismic Toss and Final
Gambit all calculate correctly. Most abilities and items are damage modifiers the calculator applies from
each sampled set; speed uses the calculator's own `getFinalSpeed`, so weather speed abilities are covered;
status-move viability covers type and ability immunities, terrains, Safeguard, powder, Good as Gold, Magic
Bounce and Prankster into Dark.

Fixed — each of these was shown to the model as a plain damage number:

| Move | Species | What the model now sees |
|---|---|---|
| Knock Off | 124 | Removes the target's item for the rest of the battle |
| Fake Out, First Impression | 8, 2 | Fails after the user's first turn out |
| Poltergeist | 12 | Fails once the target's item is gone |
| Scale Shot | 10 | +1 Speed, −1 Defence (a data field the reader missed) |
| Explosion, Healing Wish | 5, 4 | The user faints |
| Solar Beam, Meteor Beam | 3, 4 | Charges this turn; sun and Power Herb skip it; Meteor Beam's +1 SpA |
| Future Sight | 3 | Lands two turns later, on whoever is in |

Fixed in a second pass, with the payload cost measured over the same 464 decisions: across both passes,
5 decisions (1.1%) moved from the reduced to the minimal tier, and the median payload is unchanged.

## Scorecard — 16 live battles

The record is **1 win in 16** (6%; a 95% interval of 1–28%). The ninth battle had been written up as a
win, but its `win` line names the opponent; that entry is corrected. 15 of the 16 were against the same
opponent.

The knockout trend is suggestive rather than proven (Mann-Whitney p ≈ 0.06 on eight battles each). Every
row was scored with the current code, so the yardstick is fixed; it judges the model's own pick, before any
guard. The model already avoids clear blunders, so the losses come from positional play — switching,
preserving Pokémon, long-term planning — which none of these checks measure. None of the changes made on
2026-09-23 has been played live yet.
